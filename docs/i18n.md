# Localization and Internationalization

Single shared catalog drives all three companion apps. Source of truth is [i18n/locales/en.json](../i18n/locales/en.json); every other locale is AI-translated and human-reviewed. `cargo xtask i18n-gen` regenerates per-platform bundled forms; `cargo xtask i18n-sync-all` calls OpenAI to fill missing translations. Same commands are exposed as VSCode tasks (`Cmd-Shift-P → Tasks: Run Task → i18n: …`).

```
i18n/
  catalog.config.json     locales list, OpenAI model, output paths
  glossary.json           do-not-translate terms
  locales/<code>.json     per-locale catalog
  parity/                 generated cue-engine cross-platform contract
```

Wire format is ICU MessageFormat (`{name}`, `{name, number}`, `{name, select, …}`) — each platform ships a tiny resolver so all three apps render identical output. Voice cues go through a structured `cueMessage(event, distanceMode) → {key, values}` seam locked down by [i18n/parity/cue-en-snapshots.json](../i18n/parity/cue-en-snapshots.json); platform tests assert every fixture row.

Locale codes follow ISO 639-1 (`en`, `fi`, `pt`, …). When a language has multiple major variants we keep the bare code and pin the variant via `localeOptions.<code>.translatorVariant` in [catalog.config.json](../i18n/catalog.config.json) — e.g. `pt` → Brazilian Portuguese, `es` → Latin American Spanish, `zh` → Simplified Mandarin. The hint is fed to OpenAI as `Variant: …` in the prompt.

RTL languages (Arabic, Persian, Urdu) are flagged via `localeOptions.<code>.rtl` and mirrored on each platform's `SupportedLocale` enum. Web sets `<html dir="rtl">` from [setActiveLocale](../companion-web/src/i18n/index.ts); iOS injects `.environment(\.layoutDirection, .rightToLeft)` at the WindowGroup root in [ESP32MapCompanionApp.swift](../companion-ios/CompanionApp/App/ESP32MapCompanionApp.swift); Android relies on `android:supportsRtl="true"` plus the active `Locale`, both of which are already in place.

Language-name picker labels (e.g. "Suomi", "العربية", "中文") are NOT translated — they're hardcoded as native names in each platform's `SupportedLocale.nativeName` (web exports `NATIVE_LANGUAGE_NAMES`). Translating language names would cause "English" → "Englanti" in a Finnish UI, which doesn't match the iOS/Android system convention.

The firmware is intentionally not localized.

## Adding a new language

Adding e.g. Swedish (`sv`) — the only flow that's hard to grep for since it touches every platform:

1. **Catalog config:** add `"sv"` to `locales` in [catalog.config.json](../i18n/catalog.config.json). If the language has variants, add a `localeOptions.sv` block with `translatorVariant`. If it's RTL, set `rtl: true`.

2. **Empty target catalog** at `i18n/locales/sv.json`:
   ```json
   { "locale": "sv", "entries": {} }
   ```

3. **Run** VSCode → Tasks → `i18n: sync all translations` (or `cargo xtask i18n-sync-all`). OpenAI fills the catalog; `i18n-gen` auto-runs at the end and refreshes every platform's bundled output.

4. **Web** — add `sv` to `SUPPORTED_LOCALES`, import the catalog, and add a native-name entry to `NATIVE_LANGUAGE_NAMES` in [index.ts](../companion-web/src/i18n/index.ts). Extend the `AppLanguage` and `AppLanguagePref` unions in [index.ts](../companion-web/src/i18n/index.ts) and [models.ts](../companion-web/src/domain/models.ts). If RTL, add the code to `RTL_LOCALES`. The picker iterates `SUPPORTED_LOCALES`, no UI edit.

5. **iOS** — add the case to `AppLanguage`, `SupportedLocale`, `nativeName`, and `isRtl` in [Localized.swift](../companion-ios/CompanionApp/Integration/I18n/Localized.swift). Add `<string>sv</string>` to `CFBundleLocalizations` in [Info.plist](../companion-ios/CompanionApp/Info.plist). The picker iterates `AppLanguage.allCases`, no UI edit.

6. **Android** — add the case to `AppLanguagePref` and `SupportedLocale` (with `nativeName` and optional `isRtl`) in [Strings.kt](../companion-android/app/src/main/java/me/fiksu/esp32map/companion/integration/i18n/Strings.kt), and `<locale android:name="sv"/>` in [locale_config.xml](../companion-android/app/src/main/res/xml/locale_config.xml).

7. **Rebuild** the native apps; web hot-reloads.

Cost: ~85 keys × ~150 tokens on `gpt-5.4-nano` ≈ well under one cent per fresh language.

## Status semantics

Each non-EN entry has a `status` that controls re-translation:

- `ai-translated` (default) and `reviewed` — sticky as long as the EN `sourceHash` matches. EN drift triggers re-translation. Both behave identically; `reviewed` is just a human-readable "I checked this" tag.
- `locked` — never re-translate, even if EN changes. Use for hand-tuned phrases that must not be overwritten.
- A `reviewed` entry with no `sourceHash` is treated as sticky-without-drift-tracking (the user explicitly approved it for the current source).

`sourceHash` covers `value + description` — editing the EN description forces re-translation, which is usually right because translator context changed.

## Setup

Copy [.env.example](../.env.example) to `.env` and paste your `OPENAI_API_KEY`. The xtask auto-loads `.env` from the workspace root; existing shell exports still win. Switch models by editing [`catalog.config.json:openai.model`](../i18n/catalog.config.json).
